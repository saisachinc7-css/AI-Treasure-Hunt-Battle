8x8 Grid Arena

The game takes place on an 8x8 coordinate board containing random obstacles and a single target treasure.

Dual Corners

Player 1 starts at the Top-Left corner (0,0). Player 2 starts at the Bottom-Right corner (7,7).

PEAS Agent Specifications

Agent Element Description / Functionality
Performance Measure Reach the golden treasure first, minimize total moves, minimize execution/solving time, and avoid dead ends.
Environment An 8x8 discrete grid containing static randomly placed obstacles, fixed start positions, and a random treasure cell.
Actuators Orthogonal movements: Up, Down, Left, Right (movement vector adjustments).
Sensors Position sensor (current row/col), environment map sensor (obstacle placements), and target location sensor (treasure coordinates).

Breadth-First Search (BFS)

Queue (FIFO)

BFS systematically expands the search frontier level by level. In an unweighted grid with uniform step cost, BFS is guaranteed to discover the optimal path with the absolute minimum number of steps. It does not use heuristics, resulting in wider exploration of nodes.

Depth-First Search (DFS)

Stack (LIFO)

DFS drives deep down a single branch before backtracking. Since it uses a stack, it searches sequentially along paths until it hits an obstacle or boundary, backtracks, and tries another direction. It is not optimal and can find highly inefficient paths.

Greedy Best-First Search

Heuristic (Manhattan)

Greedy Best-First Search prioritizes expansion based solely on a heuristic function estimation. It calculates the Manhattan distance to the treasure: h(n) = |x1 - x2| + |y1 - y2|, and moves to the cell with the lowest value. It is fast, but easily blocked by obstacles.

A* Search Algorithm

f(n) = g(n) + h(n)

A* Search evaluates cells using a combined cost function: f(n) = g(n) + h(n). Here, g(n) is the step cost incurred from the start node to the current cell, and h(n) is the heuristic Manhattan distance to the treasure. This balances path efficiency and search speed, making it optimal and complete.

Constraint Satisfaction Features (CSP)

The game implements multiple layers of constraint satisfaction to govern all entity movements:

  • Boundary Constraint: Ensures row and column indices remain within [0, 7].
  • Obstacle Constraint: Prunes any neighbor node that overlaps with a blocked cell.
  • Forward Checking: Before any physical move, the agent scans its list of adjacent neighbors and verifies that at least one reachable path to the treasure exists from each neighbor. Neighbors with zero path solutions are flagged as invalid or pruned to prevent trapping the agent.
